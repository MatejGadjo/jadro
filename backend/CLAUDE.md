# News Aggregator Backend (Project Instructions)

## Tech stack
- **Language**: Go 1.25
- **HTTP**: Gin
- **DI**: uber/fx (wired in `internal/app/app.go`)
- **Logging**: uber/zap
- **Database**: pgx/v5 (Postgres), pgvector-go (vector(384)), go-redis/v9 (Redis)
- **Queries**: sqlc (generated in `internal/storage/sqlc/`)
- **RSS**: gofeed + go-resty (HTTP client)
- **Worker pool**: alitto/pond/v2
- **Embeddings**: yalue/onnxruntime_go + knights-analytics/hugot, daulet/tokenizers
- **Testing**: testify
- **Config**: godotenv

## Scope and goals
- MVP scope: Macedonian language, RSS feeds only, no personalization or accounts.
- Primary flow: ingest RSS → normalize → classify topic → store → generate embeddings → cluster → score → serve feeds.

## SQL / sqlc workflow

**Never manually edit files in `internal/storage/sqlc/`** — they are code-generated and have `// Code generated by sqlc. DO NOT EDIT.` headers. Manual edits will be overwritten on the next `sqlc generate` run.

Correct workflow for any SQL change:
1. Edit only the `.sql` files in `internal/storage/sqlc/queries/`
2. Run `sqlc generate` from `backend/` to regenerate `internal/storage/sqlc/*.sql.go`
3. Update the storage wrapper in `internal/storage/*.go` to expose the new/changed method
4. Map to domain models there if the query returns a new struct; update `ClusteringStore`/`EmbeddingStore` interfaces in `internal/clustering/dependency.go` (or the relevant package interface) only if the new method is needed by that package

## API contract

### Public routes (rate limited)
- `GET /api/health`, `HEAD /api/health` — health check
- `GET /api/feed?topic=&page=` — paginated cluster feed (30 req/min)
- `GET /api/articles/latest` — latest articles (60 req/min)
- `GET /api/clusters/:id` — cluster detail with articles (60 req/min)
- `PATCH /api/articles/:id/clear-image` — clear article image (20 req/min)
- `GET /api/push/config` — VAPID public key (60 req/min); 404 when push disabled
- `POST /api/push/subscribe` — store a browser subscription (20 req/min, fail-closed)
- `POST /api/push/unsubscribe` — remove a subscription (20 req/min, fail-closed)

There are no internal/admin HTTP routes; ingest and cleanup run on an in-process cron.

## Architectural notes
- DI wiring lives in `internal/app/app.go`; `cmd/api/main.go` just calls `app.Initialize().Run()`.
- A single binary serves the API and runs the ingest/cleanup cron in-process (`internal/jobs/cron.go`), wired via fx lifecycle hooks. `jobs.IngestRunner`/`jobs.CleanupJob` keep their `RunOnce` guard so overlapping runs are skipped.
- Running >1 replica would fire the cron on each — keep a single instance (or add leader election) until that changes.
- Migrations run automatically on API startup via `storage.Migrate`.
- Postgres stores articles/clusters; embeddings stored via pgvector (vector size 384).
- ONNX embeddings are optional; disabled if `ONNX_RUNTIME_LIB_PATH` is not set.
- sqlc queries are generated from SQL in `internal/storage/sqlc/`; run `sqlc generate` to regenerate.

## Intentionally absent
- No user accounts, authentication, or personalization.
- No multi-tenancy or per-user state.
- No article-level feed endpoint (feed is cluster-based).
- Do not add any of the above without explicit instruction.
